# 业务平台接入约束

本页说明会话准入、计划修订、幂等创建、现场身份和工具目录的服务端保证。

## 会话与创建任务

`POST /api/tasks` 为指定会话创建新目标。后端在一个数据库事务中锁定会话、检查归属和当前目标，再写入用户消息、任务及运行。

`queued`、`running`、`reconciling`、`waiting_input`、`waiting_approval`、`paused`、`needs_reconcile`、`interrupted` 都占用当前目标。已有目标时返回 HTTP 409：

```json
{
  "detail": {
    "code": "session_goal_open",
    "message": "会话已有未结束目标，请向当前运行提交补充要求",
    "task_id": "…",
    "run_id": "…",
    "inputs_url": "/api/runs/…/inputs"
  }
}
```

客户端应向返回的运行提交补充；暂停等控制语义仍按运行接口处理。另开目标使用新会话。完成、部分成功、失败、取消后可以在原会话开下一轮。

创建请求建议携带 `Idempotency-Key`。请求键与任务和运行编号在同一事务中关联，提交前失败全部回滚；提交后即使响应或派发中断，重试仍取得原任务，排队运行可由 Worker 领取。作用域为企业、用户和接口，指纹包含消息、会话和现场哈希。内容不同返回 409。有效重放无需重新验证已经过期的现场票。

旧版本产生的无任务编号孤立占位不能证明没有执行过，保持冲突并要求核实，禁止盲目重建。新创建流程不会产生这类占位。

## 修订计划

用户补充修订与观察后自主修订使用同一份计划元数据约束：

- 已确定的 `result_locus` 不可改变。改变目标需显式结束旧目标后另开任务，不能让模型静默把平台修改降为聊天回答。
- 原完成条件与新增完成条件合并去重；省略或空列表不会清空原要求。
- 被取代步骤若有唯一同工具的新步骤，对应 `tool_succeeded` 步骤引用跟随新编号；已完成步骤的证据保留。
- 片段策略和观察目标省略时继承；显式 `observe` 必须有观察目标。
- 元数据进入计划、快照、恢复入口和修订模型输入；模型提出结束也不能移除原验收条件。

缺工具的说明可在原业务落点下返回，但不能把说明文字当作已经完成平台修改。

## 现场票

登录主体从数据库登录会话获取外部 `subject`、`platform_id`、`connection_id`，与现场票逐项核对。外部 subject 与中台本地 user_id 是不同编号。

现场票只允许登记过的 RS256。要求 `iss`、`aud`、`sub`、`tenant_id`、`platform_id`、`ctx`、`iat`、`exp`；有效期必须为正且不超过 `AUTH_TICKET_MAX_LIFETIME`，同时检查签名、租户平台白名单、接入、公钥和现场哈希。现场票不会扩大登录主体的权限。

## MCP 工具目录

正式治理模式按可信账本中的运行和租约代次隔离工具及内部能力目录，不同运行不共用目录。每次命中前重新检查主体、凭据绑定版本、范围和密钥指纹；轮换后重新发现，缺绑定或撤权时拒绝并清空本运行的目录。缓存不保存密钥明文。

有可信运行上下文时，开发模式同样按运行隔离；只有本地无账本调用保留进程级缓存。开发模式不得作为多租户生产配置。

## 验证

`tests/test_platform_guards.py` 覆盖真实 PostgreSQL 并发准入、事务回滚、提交后重放、API 冲突、两类修订、恢复元数据、现场身份绑定和目录隔离。模型及远端发现使用受控替身，不调用真实业务平台。
