# main 与 feat/beeftv 的通用中台取舍

审查基线：main `98a1ad3`，feat/beeftv `6f27ea5`。整理前的 main 另保存在 `codex/platform-before-mcp-contract`。本次采用选择性提炼，没有整体合并业务分支。

## 已保留的通用底座

main 已经吸收分支中的能力包解耦、结果落点校验、递归引用、结果归属隔离、并发容量与 stdio 会话复用。main 对任意成功回执充当产物、部分步骤成功充当全计划完成、负数索引、歧义引用和跨任务读文件的限制比业务分支更严格，继续保留。

## 本次采纳与修正

| 分支中的经验 | 通用实现 |
| --- | --- |
| 包装器补 operationId | 工具通过可选协议声明幂等字段，中台注入已准入的动作身份；不会把参数相同的两个新动作去重 |
| 包装器修补 created/nodes、id/nodeId 等引用 | 保留并向规划器提供 outputSchema，调用返回时校验；字段含义由 Server 定义 |
| 专属环境文件与包装脚本 | stdio 环境引用与凭据变量映射；连接按主体、凭据和环境隔离 |
| 专属契约测试 | 两种行业测试 Server 经同一通道运行，加真实 Worker/PostgreSQL 测试验证动作身份 |
| 硬编码工具白名单 | 保留现有授权政策；新增只读合同检查，不根据 annotations 自动授权 |

同时修复 main 的发现缓存跨主体共享、精确工具名查找漏过可见性过滤、合法非 JSON 结果被拒、原始多分块在调用链中丢失等通用缺口。

移除 main 中按 analysis 能力名称降低优先级的启发式。它是生成场景偏好，不属于跨行业中台规则。原实现仍在业务分支和整理前快照分支中。

## 继续只留在业务分支

- BeefTV 白名单、画布模板和直接 REST 建画布。
- models 渠道展开、nodeId 别名、composerContent 等字段知识。
- 遇到重名自动改标题、遇到 revision 冲突自动换新版本重发。
- BeefTV 专属政策种子、地址、确认链接和异步合同。

这些可以用于企业实现自己的 MCP Server，不进入通用内核。新接入工具声明 `agent_hub` 时直接走通用通道；旧站点发布能力包继续兼容已有功能，没有将正常用户能力一并删除。

## 尚未实现

租户连接地址的动态管理、自动接入向导、OIDC/SSO、标准 Tasks 协商、任务相关工具检索。当前没有宣称企业已经只填 URL 就能完整上线。实际对接边界见 [MCP Server 对接协议](mcp-server-contract.md)。

## 验证

完整 unittest 套件使用独立、一次性的 PostgreSQL 测试库，开启 RuntimeWarning 错误检查。467 项全部通过，无跳过。新增的协议测试通过真实 MCP SDK 和 stdio 子进程连接库存、客服两种测试 Server；真实 Worker 测试验证注入值来自持久动作账本，结果经原有登记链路保存。模型调用使用测试替身，没有对企业真实业务系统执行写操作。
